## ابزار و محدودهٔ بازتولید

اجرای `npm run verify` قواعد ذخیره، مکانیک، پیشروی، ۲۵ عملیات و تست‌های بازیابی را می‌سنجد. `npm run build:android` بستهٔ استاتیک را برای Capacitor تولید می‌کند. برای پروب مرورگر، خروجی همان سورس را جداگانه روی localhost سرو کنید. آزمون API و ساخت استاتیک را هم‌زمان روی یک checkout اجرا نکنید.

```bash
python3 -m http.server 3310 --bind 127.0.0.1 --directory out
# in another shell
npm run test:mobile
node scripts/audit/probe-coast.cjs
node scripts/audit/probe-render-work.cjs
python3 scripts/audit/probe-combat-render.py http://127.0.0.1:3310 review/combat
python3 scripts/audit/runner.py --no-build
python3 scripts/audit/runner2.py --no-build
```

اعداد فریم مرورگر با SwiftShader تحت بار متغیر ماشین مجازی ثبت شده‌اند و برای برآورد FPS گوشی یا علت قطعی گرما کافی نیستند. آزمون مرکز/پهنای تقریبی بدنه، نمونه‌برداری گسسته از مسیر است. آزمون‌های تهدید و اسکورت، برد و زمان شلیک مربوط به قوانین داخل بازی‌اند. حرکت هندسی ثبت‌شدهٔ مدل معادل ارزیابی زیبایی انیمیشن توسط بازیکن نیست.

**BLOCKED** — داغی پس از ۳۰ ثانیه، FPS پایدار ده‌دقیقه‌ای، زمان واقعی GPU، حس لمس و تأیید صوت، لرزش، Android Share و چرخهٔ عمر روی سخت‌افزار. راهنمای آزمون و فایل‌های خروجی در [آزمون گوشی](device-performance.md) آمده‌اند.

**PARTIAL** — سه [کانسپت تصویری](concepts/README.md) برای چهار نمای اصلی آماده‌اند. در رابط موجود چهار منبع بالای نقشه، فرمان‌ها و ناوبری پایین و کنترل‌های شناور برای همان فضا رقابت می‌کنند. منتظر انتخاب صریح صاحب پروژه برای اجرای رابط جدید هستیم.

نمونه‌های عملکرد، ورودی و نبرد روی خروجی ۰٫۷٫۱ پیش از آخرین تغییر کوچک مسیر تجارت ثبت شدند؛ اثر آن تغییر در آزمون صحنهٔ نهایی، دو آزمون اسکورت و VIP و اجرای مجدد کمپین بررسی شد. اثر آن بر دمای گوشی هنوز اندازه‌گیری نشده است. آزمون‌های رندر محدود به صحنه‌ها، مدل‌ها و شرایط ثبت‌شده‌اند. بررسی همهٔ ترکیب‌های نور، زاویه، tier، سطح توان گوشی و همهٔ تعامل‌های بازیکن باز می‌ماند.

بازیابی صحنه با وضعیت واقعی نمایش خطا، دوربین و ساعت بررسی شد. رشتهٔ کمکی قدیمی `__m3d` در بعضی شکست‌های اتصال صحنه می‌تواند «ready» نمایش دهد؛ برای تصمیم‌گیری دربارهٔ قابلیت بازی از آن به‌تنهایی استفاده نکنید.

## بستهٔ منتشرشده

[ریلیز آزمایشی](https://github.com/hirbodfitnesclub-droid/strait-of-hormuz-game/releases/tag/v0.7.1-test) به کامیت `9411149bdf04dbeb7cb20ef23622bcd6b0d5b17c` اشاره می‌کند. فایل `hormuz-0.7.1-debug.apk` از همان کامیت با GitHub Actions ساخته شد. اندازهٔ فایل منتشرشده ۱۷۰۳۳۶۶۲۰ بایت است. SHA-256 آن `b5c2b6c8976dd0598b8762ff1796d454ed9df935784ee9fe838b95b74bd6541f` است. نسخهٔ مستقل دستگاه ساخت محلی نیز بررسی شد و همهٔ ۴۳۱ فایل وب داخل APK با خروجی محلی تطبیق بایتی داشتند. [مشخصات ساخت محلی](evidence/recovery/local-android.json)

در اولین تلاش مرحلهٔ انتشار، GitHub پیش‌نویس را ایجاد کرد و فهرست‌گیری بلافاصله پس از ایجاد، شناسهٔ مورد انتظار را برنگرداند. انتشار متوقف شد. اجرای دوبارهٔ همان job فقط از Artifact بررسی‌شدهٔ همان build استفاده کرد؛ هش دارایی مقصد پیش از انتشار روی همان پیش‌نویس تطبیق داده شد. Workflow برای پیش‌نویس تازهٔ نسخه‌های بعدی، شناسه را از پاسخ مستقیم ایجاد می‌گیرد. این مسیرِ اصلاح‌شدهٔ ایجاد پیش‌نویس با انتشار نسخهٔ بعدی در GitHub قابل آزمون است.

**FAILED — نصب به‌صورت به‌روزرسانی روی APK قبلی.** هر دو APK مستقیماً از GitHub دانلود شدند. گواهی Debug نسخهٔ ۰٫۷٫۰ با `fff77af5` و گواهی نسخهٔ ۰٫۷٫۱ با `4e228452` شروع می‌شود. برای نگهداری پیشرفت، قبل از حذف نسخهٔ قبلی از تنظیمات فایل پشتیبان را خارج از برنامه ذخیره کنید و در نسخهٔ جدید بازیابی کنید. نصب تازه و بازگردانی فایل، مسیر آزمون این دو نسخه است. کلید خصوصی runner قبلی در خروجی APK یا این مخزن وجود ندارد.

**VERIFIED — کنترل مستقل فایل دانلودی.** بایت‌های دریافت‌شده و امضای هر دو ریلیز مستقلاً با `sha256sum` و `apksigner verify` بررسی شدند. محتوای وب از داخل APK منتشرشدهٔ ۰٫۷٫۱ استخراج و با Chromium اجرا شد. بازآزمایی ۸۰۰۴ موقعیت روی همین فایل دانلودی صفر برخورد مرکز/پوش بدنه با خشکی ثبت کرد. روی همین بسته ۶۵ شلیک با خطای مبدأ صفر، حرکت توپ در ۵۷ رسم، حرکت جرثقیل اسکله در ۱۱ رسم و سه غرق‌شدن دیده شد. این آزمون لایهٔ وب/Three داخل بسته را اجرا می‌کند. اجرای بومی خود APK نیازمند دستگاه است.
