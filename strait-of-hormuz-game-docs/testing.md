# آزمون و اعتبارسنجی نسخهٔ 0.7.0

این گزارش مربوط به درخت کاری اصلاح‌شدهٔ 2026-11-17 بر پایهٔ commit `575163b` است؛ انتشار، push یا اجرای CI در GitHub انجام نشده است. نتایج ماشینی و مشخصات خروجی در [validation.json](validation.json) ثبت شده‌اند. PASS هر ردیف فقط همان آزمون را تأیید می‌کند، نه نبودن همهٔ اشکال‌ها یا کیفیت نهایی محصول روی گوشی.

## محیط و فرمان‌ها

Linux، Node 24، TypeScript 5.9، Next 16.4.6، Chromium سیستم با SwiftShader، JDK 21، Android SDK 36، build-tools 35.0.0، Gradle 8.11.1 و AGP 8.9.1 استفاده شدند. مرورگر برای آزمون رابط و بستهٔ استاتیک است؛ دستگاه اندرویدی یا GPU گوشی در این محیط در اختیار نبود.

```bash
npm ci
npm run verify
npm run build:android
python3 -m venv /tmp/hormuz-audit-venv
/tmp/hormuz-audit-venv/bin/pip install -r scripts/audit/requirements.txt
python3 -m http.server 3310 --bind 127.0.0.1 --directory out
```

در ترمینال دیگر، پس از پایان ساخت:

```bash
AUDIT_CHROMIUM=/usr/bin/chromium npm run test:mobile
AUDIT_CHROMIUM=/usr/bin/chromium AUDIT_PYTHON=/tmp/hormuz-audit-venv/bin/python python3 scripts/audit/runner.py --no-build
AUDIT_CHROMIUM=/usr/bin/chromium AUDIT_PYTHON=/tmp/hormuz-audit-venv/bin/python python3 scripts/audit/runner2.py --no-build
bash android/gradlew -p android assembleDebug bundleRelease :app:lintDebug :app:lintRelease
```

مسیر Chromium را با نصب محلی تطبیق دهید؛ Node Playwright از dependency پروژه استفاده می‌کند و پروب Python بستهٔ جداگانه دارد. هنگام آزمون مرورگر `out/` را بازسازی نکنید. به‌دلیل جابه‌جایی موقت APIها، build استاتیک را هم‌زمان با typecheck یا تست API روی همان checkout اجرا نکنید. `--no-build` فقط برای خروجی تازهٔ همان سورس معتبر است. پروب‌ها cache مرورگر را زیر `review/audit-profile` نگه می‌دارند؛ `AUDIT_PROFILE` و `AUDIT_PYTHON` قابل تنظیم‌اند.

## صحنه و انیمیشن

`runner.py` با **۲۰ PASS، صفر FAIL و صفر SKIP** تمام شد: ترکیب/فاصلهٔ ورود در موج‌های ۱، ۳، ۵ و ۱۰ (۸ بررسی)، اقتصاد زنده (۴)، صحنه و مدل GLB (۳)، و cadence سیلو/توپ/EW/لیزر/MLRS (۵).

`runner2.py` پس از اصلاح مدل‌ها و ابزار I5 با **۳۰ PASS، صفر FAIL و صفر SKIP** تمام شد: حرکت ۱۸ پیکربندی برجک، وجود اتصال انیمیشن ساختمان و تغییر واقعی چهار ساختمان متحرکِ حاضر (۲۳ بررسی)، بودجهٔ هندسه/DPR/سقف رندر (۴)، دو مسیر مرحلهٔ ۳ (۲) و شلیک زندهٔ I5 (۱). I5 در `battle.elapsed=35.62` تعداد ۲۷۸ شلیک و ۵۳۸ رویداد FX ثبت کرد؛ مرجع reducer جداگانه در ۳۰ ثانیه ۱۹۷ شلیک داشت. این سنجه، فعال‌بودن مسیر شلیک را نشان می‌دهد و به معنی برابری فریم‌به‌فریم دو اجرا نیست.

فایل JSON هر ممیزی در `evidence/` نگهداری می‌شود. ممیزی اول پیش از اصلاح نهایی preview و export ساختمان اجرا شد؛ کد نبرد پس از آن تغییر نکرد. ممیزی دوم و بازآزمایی صحنه بر بستهٔ اصلاح‌شدهٔ انیمیشن اجرا شدند؛ پس از آن فقط متن اعلان فروش برجک تصحیح شد. آزمون‌های نهایی رابط، آفلاین و بازیابی بر بستهٔ تحویلی‌اند. هش جداگانهٔ هر بسته در `validation.json` دامنهٔ شواهد را مشخص می‌کند؛ runner از خروجی تاریخی برای قبول اجرای تازه استفاده نمی‌کند.

در ممیزی نهایی heat، میانهٔ نمای آغاز ۴۲۵۱۴۳ مثلث، ۳۵۹ draw call و DPR=1 بود. شمارش رندر نبرد حدود ۱٫۳۳ فریم در ثانیهٔ واقعی گزارش کرد. این نرخ مربوط به SwiftShader ماشین آزمون است و تخمین FPS گوشی نیست. پروب heat بودجهٔ هندسه/DPR و وجود سقف رندر را می‌سنجد؛ عبور از آزمون نرخ کمتر از ۶۰ در این VM کند به‌تنهایی اثبات محدودکننده نیست و کنترل ساختار کد نیز جدا اجرا می‌شود. اندازه‌گیری باتری، حرارت، حافظه و پایداری فریم گوشی انجام نشده است.

## ساخت، وابستگی و حدود انتشار

`npm run build:android` با Next 16.4.6 موفق و هر چهار افزونهٔ Capacitor همگام شد. Gradle، APK debug و AAB release را ساخته است؛ debug امضای آزمایشی معتبر v1/v2 دارد و AAB بدون امضای مالک است. `aapt` شناسهٔ `ir.hormuz.sovereign`، نسخهٔ 0.7.0/code7، min23 و target36 را تأیید می‌کند. هیچ فایل `.so` در بسته‌ها پیدا نشد. مشخصات خروجی نهایی و lint بومی در `validation.json` هستند.

lint بومی در هر دو حالت debug/release صفر خطا و ۲۷ هشدار دارد: منابع و شکل/تکرار آیکون، splash قدیمی، پیشنهاد نسخهٔ جدید کتابخانه و هشدار جهت ثابت نمایشگر. هشدارها حذف یا به‌عنوان «صفر هشدار» گزارش نشده‌اند؛ پذیرش جهت و نمایشگر بزرگ جزو آزمون دستگاه واقعی است. بررسی CRC هر دو آرشیو نیز موفق بود.

آخرین `npm audit --json` در برنامهٔ اصلی صفر آسیب‌پذیری شناخته‌شده گزارش کرد. ابزار مستقل پک ساختمان نیز پس از ارتقای Vite به 7.3.8 و esbuild به 0.28.2 صفر مورد دارد و build آن موفق است. این نتیجه به پایگاه advisory و lockfile زمان آزمون وابسته است و ممیزی امنیت کامل نیست. هماهنگی lockfile اصلی با `npm ci --dry-run --ignore-scripts --audit=false` کنترل شد؛ نصب کاملاً تازهٔ dependencyها در ماشین دوم انجام نشده است. workflow کیفیت آماده است، اما اجرای GitHub Actions در این مأموریت انجام نشده است.

مشکلاتی که آزمون در همین مأموریت آشکار کرد و اصلاح شدند، شامل توقف اشتباه intermission پس از hydration، اجرای پنهان نبرد پیش از آمادگی صحنه، بولتن تکراری هنگام بازیابی، تفاوت زمان/وضعیت مؤثر نبرد پس از ذخیره، خط رهگیری خارج دسترس دفاع اولیه، و خطای build ناشی از cache تایپ مسیرهای Next بود. در runner، skip اکنون پذیرش موفق نیست و خروجی قدیمی قبل از هر پروب پاک می‌شود؛ خطای اجرا نمی‌تواند PASS قبلی را به ارث ببرد.

اجرای اول ممیزی دوم ۲۴ PASS و دو FAIL داشت و مدرک آن در `evidence/audit-2-before-fixes.json` حفظ شده است. یکی خطای واقعی خروجی مدل ساختمان بود: نام محورهای متحرک در GLBها وجود نداشت و ساختمان‌ها انیمیشن نداشتند؛ منبع پک و exporter اصلاح و هر ۵۵ مدل بازتولید شد. دیگری ایراد ابزار I5 بود: پنجرهٔ توضیح عملیات نبرد را طبق طراحی مکث می‌کرد، ولی ابزار گذشت زمان اقتصاد را «۳۵ ثانیه نبرد» می‌نامید. اکنون پنجره از کنترل واقعی رابط بسته و `battle.elapsed` سنجیده می‌شود. هیچ‌یک با skip، خاموش‌کردن رفتار محصول یا قبول نتیجهٔ قدیمی حل نشده‌اند.

## اعتبارسنجی باقی‌مانده

آزمون همین binary روی گوشی واقعی، وقفه و kill/relaunch، افزونه‌های بومی، صدا، فریم/حرارت/مصرف ۳۰ دقیقه‌ای و Android 16/نمایشگر بزرگ انجام نشده است. PostgreSQL واقعی، IAP/تبلیغات، سرویس تحلیل جمعیت و پنل فروشگاه نیز آزموده نشده‌اند؛ سه مورد آخر در محصول حاضر پیاده نشده‌اند. cohort بالغ واقعی، مخرج کامل نصب‌ها و مطالعهٔ بازیکن موجود نیست؛ D20≥90٪، LTV و رقابت با پنج بازی برتر تأیید نشده‌اند. امضای مالک، سیاست عمومی و اطلاعات ناشر و review فروشگاه طبق [release.md](release.md) برای انتشار باقی‌اند.
